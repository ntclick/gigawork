# ERC-8183: Agentic Commerce — Escrow Flow

> **Manus note:** File này mô tả toàn bộ vòng đời ERC-8183. Cần 3 diagram:
> 1. State machine của Job (Open → Funded → Submitted → Completed)
> 2. Sequence diagram: User-as-Client flow (3 wallet popups)
> 3. Sequence diagram: Admin-self-loop flow (không cần user ký)

## Tổng quan

ERC-8183 là chuẩn "Agentic Commerce" — cho phép một AI agent (provider) thực hiện công việc và nhận thanh toán USDC tự động qua smart contract escrow. Không cần trust: tiền bị khóa trong contract, chỉ release khi provider submit deliverable và evaluator confirm.

**Contract:** `0x0747EEf0706327138c69792bF28Cd525089e4583` (Arc Testnet)

---

## Các vai trò

| Vai trò | Trong GigaWork | Mô tả |
|---------|---------------|-------|
| **Client** | User (Privy wallet) | Tạo job, nạp USDC vào escrow |
| **Provider** | Admin wallet | Nhận job, thực hiện công việc, submit deliverable |
| **Evaluator** | Admin wallet | Xác nhận deliverable, hoàn tất payment |

> **Note:** Trong triển khai hiện tại, Provider và Evaluator đều là cùng một admin wallet. Trong production nên tách biệt để tránh xung đột lợi ích.

---

## Job Status

```
0 = Open       (job created, chưa funded)
1 = Funded     (USDC đã lock trong escrow, sẵn sàng cho provider)
2 = Submitted  (provider đã submit deliverable hash)
3 = Completed  (evaluator đã complete, USDC released)
```

> **Manus note:** Vẽ state machine diagram:
> `Open` →(fund)→ `Funded` →(submit)→ `Submitted` →(complete)→ `Completed`
> Thêm: Funded →(cancel/expire)→ Cancelled (nếu có trong contract)

## Flow 1: User-as-Client (ERC8183_USER_CLIENT=1)

Người dùng giữ quyền kiểm soát tiền của mình. Cần ký 3 tx.

> **Manus note:** Vẽ sequence diagram chi tiết. Actors: User, Browser (useEscrowPost), Next.js API, Arc Chain.

### Bước 1 — Prepare (Server trả calldata)

```
POST /api/workflow/route.ts
  → tạo workflow row (status=awaiting_fund)
  → trả về escrow: "user-client"

POST /api/workflow/escrow/prepare
  → gọi prepareOpenAndFund(clientAddress, description, budgetUsdc)
  → trả về:
      createCalldata: encode createJob(provider=admin, evaluator=admin, expiredAt, description, hook=0x0)
      approveCalldata: encode approve(spender=AGENTIC_COMMERCE, amount=MAX_UINT256) [nếu cần]
      budget: wei string
      needsApprove: boolean
```

### Bước 2 — User ký createJob (Popup #1)

```
Browser gửi tx createJob lên Arc Chain
Arc Chain phát sự kiện: JobCreated(jobId, client, provider)

POST /api/workflow/escrow/post-create
  → Server chờ receipt của createTx (polling 80s)
  → Gọi setBudgetByAdmin():
      - Parse JobCreated event → lấy jobId
      - Gửi setBudget(jobId, budget, "0x") từ admin wallet
  → Trả về: jobId + fund calldata
```

**Fallback RPC chain (nếu primary RPC chậm):**
```
pollingClient (primary Arc RPC)
→ drpc.testnet.arc.network
→ quicknode.testnet.arc.network
→ blockdaemon.testnet.arc.network
→ ARC_RPC_URL env
→ NEXT_PUBLIC_ARC_RPC env
```

### Bước 3 — User ký approve + fund (Popup #2 & #3)

```
Browser gửi:
  1. USDC.approve(spender=AGENTIC_COMMERCE, amount=MAX_UINT256)  [nếu needsApprove]
  2. AgenticCommerce.fund(jobId, "0x")

POST /api/workflow/escrow/confirm
  → verifyApproveAndFund():
      - Kiểm tra approve tx: target=USDC, function=approve, spender đúng, amount≥budget
      - Kiểm tra fund tx: target=AgenticCommerce, function=fund, jobId đúng, signer=canonicalClient
  → UPDATE workflows: status=planning, persist approveTx + fundTx
  → Trả về: { ok: true, jobId, fundTx }
```

Sau khi confirm xong, workflow status = `planning` → Hermes tự động start.

## Flow 2: Admin Self-Loop (ERC8183_USER_CLIENT=0)

Admin tự nạp tiền cho workflow (không cần user ký).

```
POST /api/workflow
  → openAndFundJob(description, budgetUsdc, expirySeconds)
     Gửi 4 tx tuần tự từ admin wallet:
       1. createJob(provider=admin, evaluator=admin, ...)
       2. approve(AGENTIC_COMMERCE, MAX_UINT256) [nếu cần]
       3. setBudget(jobId, budget, "0x")
       4. fund(jobId, "0x")
  → status = planning ngay lập tức
```

## Flow 3: Settlement (sau khi Hermes xong)

> **Manus note:** Vẽ sequence diagram. Actors: finalizeWorkflow.ts, AgenticCommerce contract, DB.

```
publishFinalReport()
  → settleWorkflowJob(workflowId, finalMarkdown)
      1. Kiểm tra erc8183JobId tồn tại
      2. Đọc on-chain status: phải là 1=Funded
      3. submit(jobId, keccak256(deliverableSeed), "0x")
          → trả về submitTx
          → job status = Submitted
      4. complete(jobId, keccak256(reasonSeed), "0x")
          → trả về completeTx
          → job status = Completed
          → USDC released từ escrow về provider (admin)
      5. Lưu submitTx, completeTx, deliverableHash vào DB
  → status = completed
```

## Idempotency

Mỗi bước đều safe để retry:

| Endpoint | Kiểm tra idempotency |
|----------|---------------------|
| `/prepare` | Nếu fundTx đã có: trả về shortcut |
| `/post-create` | Nếu erc8183JobId đã có: trả về existing state |
| `/confirm` | Nếu status ∈ {planning, completed, settling}: trả về ok=true |
| `settleWorkflowJob` | Đọc on-chain status, skip nếu đã Submitted/Completed |

## Xử lý lỗi

### User từ chối ký (Wallet Rejection)

Frontend (`useEscrowPost.ts`) nhận diện:
- EIP-1193 error code `4001`
- Viem `UserRejectedRequestError`
- Message chứa "User rejected", "action_rejected"

→ Hiển thị "Bạn đã huỷ ký giao dịch", reset về step=idle

### Tx chậm xuất hiện trên chain

`/post-create` polling pattern:
- 80 lần × 1s = 80 giây max
- Sau 44 polls: đặt cờ `dropMissingTx=true`
- Nếu vẫn không thấy tx: trả về `create_tx_not_found`, frontend reset

### Không đủ USDC

Frontend detect via viem error → hiển thị "Ví không đủ USDC hoặc gas"

## Lưu ý quan trọng

- **USDC là gas token** trên Arc Testnet (18 decimals), khác với USDC ERC-20 trong contract (6 decimals). Custom `arcTestnet.ts` fix lỗi này trong viem.
- **Admin queue** serialize tất cả admin tx để tránh nonce collision: `adminTxQueue: Promise<unknown>`.
- **Budget mặc định:** `ERC8183_BUDGET_USDC=0.05` USDC. Có thể điều chỉnh trong env.
- **Expiry:** Job hết hạn sau `ERC8183_EXPIRY_SECONDS` (default 86400 = 1 ngày).
